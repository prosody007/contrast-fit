One background. A measured UI palette.

Fit the contrast.
Keep the context.

ContrastFit turns one opaque background into semantic colors for text, surfaces, charts, and status labels. When the input cannot support your contrast targets, it fits the content background instead of quietly lowering the bar—and keeps the original choice and the repair visible.

Deterministic JavaScript. Zero runtime dependencies. Modern browsers and Node.js 22+. Try a background in the live demo or read the complete API.

From a color choice to a usable starting point

Dynamic backgrounds, predictable text

User-selected colors can leave fixed light/dark themes in the middle. Fit foregrounds and, when needed, the content background to explicit targets.

One semantic vocabulary

Generate the same 17 roles for cards, dashboards, and charts instead of hand-maintaining unrelated color values for every theme.

Inspect the actual result

Keep original and resolved backgrounds separate. Inspect final-color ratios, effective alpha composites, target flags, and recorded adjustments.

Three steps to integrate

1. Choose the input

Pass an opaque three- or six-digit hex background. Keep the defaults or set explicit text, muted, series, and surface targets.

2. Generate and inspect

Call createContrastFit. Read the resolved background, numeric results, and any repairs. Choose preserve mode only when exact input pixels are mandatory.

3. Apply and validate

Consume the CSS variables and chart dash/marker instructions. Test the rendered layers, labels, interactions, and accessibility in your application.

A repair you can explain

Mid-gray cannot support the default 8:1 text target, even with black or white text. The default auto strategy finds a nearby passing background along black/white mixing paths; it does not pretend the original input passed.

Requested

#777777 background
Best black text: approximately 4.69:1
Below the 8:1 target.

Resolved

#A0A0A0 content background
#000000 text: approximately 8.03:1
The requested target is retained.

Traceable

inputBackground retains #777777. A background adjustment records the change. The original can still frame the content.

This is the current default result, not a global minimum over all RGB colors. See how the fitting algorithm works.

Install the first public release

ContrastFit 0.1.0 is published on npm under latest, with independently verified registry bytes and installed consumers. This is an early-access 0.x API, not a 1.0 stability promise. For CommonJS, browser globals, TypeScript, and local source builds, see the distribution guide and API reference. 

npm install contrast-fit
# Or pin the first public release:
npm install contrast-fit@0.1.0
import {
  createContrastFit,
  applyPaletteToElement,
} from "contrast-fit";

const card = document.querySelector(".card");
const palette = createContrastFit("#777777");

if (card) {
  applyPaletteToElement(card, palette);
}

console.log(palette.inputBackground); // #777777
console.log(palette.background);      // #A0A0A0
console.log(palette.adjustments);     // inspect the applied repair
.card {
  background: var(--contrast-fit-bg);
  color: var(--contrast-fit-text);
}

.card__secondary {
  color: var(--contrast-fit-muted);
}

Writing custom properties does not restyle a page by itself: the host stylesheet must use them. Alpha-bearing surfaces are measured as one layer directly over the resolved background, not as arbitrarily nested translucent cards.

17 roles, not a bag of swatches

Text and muted text, two surfaces, supporting chart graphics, three series, and two status pairs share one resolved background. Seven alpha-bearing roles also expose their applied alpha and effective opaque color for inspection or alternate rendering.

Portable calculation, deliberate rendering

Browser or server

Use named exports through ESM or CommonJS, or a built browser script exposing globalThis.ContrastFit. Calculation and CSS-map generation do not need a DOM.

Your framework, your styles

Apply variables to one element, or pass a CSS map through your renderer. No bundled React/Vue adapter, WASM module, or CLI is required or claimed.

Charts beyond color alone

Render circle/square/diamond markers and solid/9 5/2 5 line patterns. Match the legend, and provide labels or a data table.

The Studio shows a short project/status list, three static product cards, a brief article/callout, and a truthful chart together in an all-visible gallery. Change colors, not business state. Each has an independent background picker, hex field, presets and reset; the real engine fits the palette automatically. Legacy independent dashboards remain available. The palette result stays framework-independent; the host owns layout, geometry, semantics, and interactions.

Measured contrast, honest boundaries

Defaults are 8:1 for text, 4.7:1 for muted text, 3.3:1 for series, and 4.5:1 for panel/metric text and status pairs. usable means all measured numeric contrast targets pass. It excludes color-only series distinctness and cannot detect whether your renderer applies the supplied chart styles.

Preserve mode can leave unresolved targets. An auto-fitted palette is still not a whole-page WCAG certificate or a color-vision-deficiency guarantee. Gradients, images, nested alpha, typography, non-text graphic visibility, focus states, and surrounding content require integration review. The engine measures final quantized colors and checks fractional composites during surface fitting; your browser renders the complete page.

Core regressions, rendered contrast samples, chart-data checks, and automated axe checks provide evidence for defined cases—not universal accessibility. See architecture and test scope and contribution checks.
